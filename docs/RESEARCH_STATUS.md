## 关键结论与证据边界

- 检索命中率不是修复率。v2→v4 同时改动提示、工具和预算，0.01 上升不能归因于定位器一项。
- 现有 33 题验证和 14 题外部诊断均曾被观察，不是盲测；未来比较要按 task 配对，并寻找新仓库/时间划分。
- 公开 0.12 基线有复制者自报 0.08；没有证据保证复现分数一致。社区推测 public=58 题未经官方确认。
- 我们没有本地真实 Gemma 轨迹，没有同配置重复运行，没有同款 GPU 显存/吞吐实测，也没有训练 adapter。
- 父子 Agent 分离搜索上下文可能有价值，但没有同预算实验证明优于单 Agent。确定性工具承担查找/裁剪，模型仍须理解根因。
- `skip_summarization=true` 不是单纯压缩上下文：当前 ADK 将工具响应视为 final，外层 harness 在未提交时可发 continuation nudge 继续。不要把它当作未经验证的无缝阶段切换。

## 对早期仓库结论的更正

| 早期说法 | 当前结论 |
|---|---|
| 不能提交 Python，只能 YAML | 可以通过 skill scripts 提交 Python；不等于能替换评分器、注册任意根工具或安装依赖 |
| eval_config.yaml 不会被读取 | 外层 scorer 读取四个字段；直接使用本地 wheel CLI 时需显式传对应参数 |
| 单题压预算解决了最初平台错误 | 主办方确认过资源配置故障；不能把恢复评分归因于我们的优化 |
| thinking_budget 数字可限制推理 | 当前桥接未转发该数值；include_thoughts=false 转 enable_thinking=false |
| 模拟 e2e 通过代表模型会修复 | 只证明流程，真实模型行为尚未测得 |
| 所有图/向量当前仍是空文件 | 旧下载存在别名空文件问题；现有审计的别名副本一致；异步函数覆盖缺口仍需注意 |
| 小模型代理的相对排序能直接指导31B | 只能作辅助诊断，不能保证架构排名能迁移到官方量化31B |
| LoRA 尚未确认修复 | 主办方9/28称昨日已修复加载；仍需自己的实际生效检查 |
